# `@bogdanrn/yt-embed` — Design Spec

**Status:** approved (brainstorming session 2026-04-27)
**Author:** Bogdan Radu
**License:** MIT, copyright 2026 Bogdan Radu
**Supersedes:** `plan.md` (root) — that file is the implementation roadmap; this file is the design contract.

## 1. Context and goals

A modern, dependency-free, MIT-licensed npm package that wraps Google's [YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference) in a Promise-based, `EventTarget`-based, TypeScript-strict class.

This is a **brand-new package with no users** and **no compatibility obligations** to any prior package (in particular, no relation to `gajus/youtube-player`'s public API). Decisions are made on merit, not legacy.

The repository at `/Users/bogdan/Work/abstract-youtube-player/` contains:
- `inspiration/` — the original `gajus/youtube-player` source, kept locally as reference, gitignored so it never lands on the published GitHub repo or in npm artifacts.
- `plan.md` — the originating implementation roadmap. Authoritative for repo bootstrap steps; superseded by this spec for behavioral and design decisions.
- `docs/superpowers/specs/` — this spec.

The package is small (~150 LOC of behavior). The goal is **minimum maintenance**: structure the code so that Google API drift requires zero code changes for additions, and one-PR changes for renames/removals.

## 2. Naming and ergonomics

### 2.1 Method names — strict 1:1 with Google `YT.Player`

Method names on the class match the names on Google's `YT.Player` interface exactly, including Google's quirks (`unMute` with capital M, `getVideoLoadedFraction`, `getVideoEmbedCode`, etc.). **No sugar aliases** in v1.

The complete method list is autogenerated from `@types/youtube`'s `YT.Player` interface (see §7) — adding a new method to that interface automatically extends the class surface.

### 2.2 Event names — DOM-style (strip `on`, lowercase)

Google's callback property names like `onStateChange` are converted to `statechange` for `addEventListener`. This matches `WebSocket`, `HTMLMediaElement`, `EventSource`. The transformation is deterministic: strip `on` prefix, lowercase the rest.

Event names are autogenerated from `YT.Events`' `on*` properties (see §7).

### 2.3 No invented semantics

The original `volumechange` event is a Gajus invention — Google's API does not emit it. In this package, `volumechange` is shipped as an **opt-in extension**, not a core event (see §4).

## 3. Public API

### 3.1 Class shape

```ts
import { YTEmbed } from '@bogdanrn/yt-embed';

const player = new YTEmbed(elementOrId, {
  videoId: 'M7lc1UVf-VE',
  width: 640,
  height: 360,
  playerVars: { autoplay: 1 },
  signal: abortController.signal,
  extensions: [],
});

await player.whenReady();
await player.playVideo();
```

- **`class YTEmbed extends EventTarget`** — synchronous constructor. The instance exists immediately; consumers may call `addEventListener` before YT's `<script>` has loaded or `YT.Player` has been constructed. No event is missed.
- **Module evaluation is side-effect-free** — no `window` or `document` access at import time. SSR-safe (Next.js, SvelteKit, Astro can `import { YTEmbed }` server-side without crashing; just don't *instantiate* on the server).
- **Constructor target** accepts `HTMLElement | string`. String is treated as element ID. If the lookup fails: `throw new TypeError("YTEmbed: target element not found")`.
- **No "wrap an existing `YT.Player`" mode** — explicitly out of scope.
- **No `events` option** — events flow exclusively through `addEventListener`. If a user passes `events`: typed away by TS, and silently ignored at runtime.

### 3.2 Constructor options

```ts
interface YTEmbedOptions {
  videoId?: string;
  width?: number;
  height?: number;
  playerVars?: YT.PlayerVars;       // re-exported from @types/youtube
  signal?: AbortSignal;             // aborting equivalent to destroy()
  extensions?: readonly Extension[];
  initTimeoutMs?: number;           // default 30_000; rejects whenReady on overshoot
}
```

### 3.3 Methods (Promise-returning, auto-queued until ready)

Every method awaits readiness internally. Calling `player.playVideo()` before `onReady` queues; resolves in call order after ready. No "called too early" footgun.

The method list is the autogenerated `FunctionName` union from `YT.Player`. Each method is a thin wrapper that forwards arguments to the underlying `YT.Player` instance. The wrapper accepts an additional optional **last argument** of type `MethodCallOptions`:

```ts
interface MethodCallOptions {
  awaitState?: boolean;             // default false
  signal?: AbortSignal;             // cancels the wrapper's promise
}

// Semantics of `signal`:
// - Aborted before the call is forwarded to YT.Player (i.e. while still
//   queued waiting for ready): the call is dropped; the promise rejects
//   with the signal's `AbortError`.
// - Aborted after the call has been forwarded but while waiting on
//   `awaitState`: the wrapper stops waiting and rejects with `AbortError`.
//   The underlying YT.Player call has already happened — we cannot un-call
//   it.
// - Aborted with `awaitState: false`: rare race; if the abort lands before
//   the forward fires, the call is dropped; otherwise it is a no-op (the
//   promise has already resolved).
```

When `awaitState: true`, the wrapper resolves **on the next `statechange` event** rather than immediately after the call returns. This is the replacement for the original library's `strictState` flag — generic, not curated per-method.

**No internal timeout.** If a user wants a timeout on `awaitState`, they compose `AbortSignal.timeout(ms)`. Documented pattern in README:

```ts
await player.playVideo({
  awaitState: true,
  signal: AbortSignal.timeout(3000),
});
// AbortError thrown after 3s if no statechange fires.
```

```ts
// Combining user abort with a timeout
const userAbort = new AbortController();
await player.seekTo(120, true, {
  awaitState: true,
  signal: AbortSignal.any([userAbort.signal, AbortSignal.timeout(5000)]),
});
```

The signature for the typed wrapper is generated from `YT.Player` so positional args from Google's API pass through unchanged.

### 3.4 Synchronous getters

```ts
player.iframe:    HTMLIFrameElement | null;   // null until ready, then stable
player.state:     PlayerStateCode;            // -1 (UNSTARTED) until ready
player.destroyed: boolean;                    // flips true after destroy()
```

Both `state` (sync, cached) and `getPlayerState()` (Promise, queries YT) are exposed; they serve different ergonomics.

### 3.5 Lifecycle

- `player.whenReady(): Promise<void>` — resolves once the `<script>` has loaded, `YT.Player` has been constructed, and `onReady` has fired. Multiple calls share one underlying promise. Rejects if:
  - the iframe API `<script>` fails to load → `IframeApiLoadError`
  - the `YT.Player` constructor throws → `PlayerInitError`
  - readiness does not arrive within `initTimeoutMs` (default 30 000) → `PlayerInitError`
  - `destroy()` is called before ready → `PlayerDestroyedError`
- `player.destroy(): void` — **idempotent**. Removes iframe, drops listeners, detaches all extensions, rejects all pending method promises with `PlayerDestroyedError`. Safe in React StrictMode double-invoke scenarios.
- Constructor `signal` aborted → equivalent to calling `destroy()`. If the signal is **already aborted** at construct time, `destroy()` runs synchronously at the end of the constructor; the instance ends construction with `destroyed === true` and no `<script>` is injected.

### 3.6 Errors

Custom error subclasses, all exported from the package barrel:

- `IframeApiLoadError extends Error` — `<script>` load failed. `cause` set to the underlying `error` event.
- `PlayerInitError extends Error` — `YT.Player` constructor threw, or readiness deadline exceeded. `cause` set to the underlying error if any.
- `PlayerDestroyedError extends Error` — method call after `destroy()`, or pending call interrupted by `destroy()`.
- `TypeError` — bad input (target element not found by ID, etc).

### 3.7 Generic escape hatch

For methods Google adds before this package ships a hand-typed wrapper:

```ts
player.call<K extends FunctionName>(
  method: K,
  ...args: Parameters<YT.Player[K]>
): Promise<ReturnType<YT.Player[K]>>;
```

`FunctionName` is the autogenerated union (§7). Types come from `@types/youtube`. Users get full typing for any method on `YT.Player` immediately after a Renovate bump of `@types/youtube`, without waiting on us to ship a sugared wrapper.

The fallback signature also accepts arbitrary string for the `method` argument, returning `Promise<unknown>` — useful for runtime-only access during transition windows.

### 3.8 Events

```ts
type PlayerStateCode = -1 | 0 | 1 | 2 | 3 | 5;

interface YTEmbedEventMap {
  ready:                 CustomEvent<{ player: YTEmbed }>;
  statechange:           CustomEvent<{ state: PlayerStateCode }>;
  playbackqualitychange: CustomEvent<{ quality: string }>;
  playbackratechange:    CustomEvent<{ rate: number }>;
  error:                 CustomEvent<{ code: number; message: string }>;
  apichange:             CustomEvent<void>;
}

class YTEmbed extends EventTarget {
  addEventListener<K extends keyof YTEmbedEventMap>(
    type: K,
    listener: (ev: YTEmbedEventMap[K]) => void,
    options?: AddEventListenerOptions | boolean,
  ): void;
  // Standard EventTarget fallback — supports any event name including
  // future YT events not yet listed in YTEmbedEventMap.
  addEventListener(
    type: string,
    listener: EventListenerOrEventListenerObject,
    options?: AddEventListenerOptions | boolean,
  ): void;
}
```

Internal mapping: when `YT.Player` is constructed, the package registers a handler for **every name** in the autogenerated `eventCallbackNames` list. Each callback re-emits a `CustomEvent` with the lowercased-name and a `detail` payload appropriate to the event. New YT events that ship via `@types/youtube` are subscribable at runtime as soon as the typings are updated, even before `YTEmbedEventMap` lists them.

Composes naturally with `AbortSignal`:

```ts
const ac = new AbortController();
player.addEventListener('statechange', (e) => …, { signal: ac.signal });
ac.abort(); // listener removed, no manual unsubscribe needed
```

## 4. Extensions

Extensions are first-class, per-instance, and lazy.

### 4.1 Interface

```ts
interface Extension {
  events: readonly string[];
  attach(player: YTEmbed): () => void;   // returns detach function
}
```

An extension declares which event names it emits. The `attach` function is called the first time a listener for any of those events is registered; it returns a cleanup function called when the last such listener is removed (or on `destroy()`).

### 4.2 Lazy attach / detach

`YTEmbed` overrides `addEventListener` and `removeEventListener` to maintain a per-event-name listener count.

- First subscriber for an event in `extension.events` → call `extension.attach(player)`, store the returned detach function.
- Last unsubscribe from all of an extension's events → call detach.
- `destroy()` → call detach for every still-attached extension.

Extensions that haven't been used cost nothing (no timers, no extra wiring).

### 4.3 Built-in: `volumeChangeExtension`

Synthesizes a `volumechange` event. Google's API does not emit volume changes; this extension uses a **hybrid** approach:

```ts
import { YTEmbed, volumeChangeExtension } from '@bogdanrn/yt-embed';

const player = new YTEmbed(el, {
  videoId,
  extensions: [volumeChangeExtension({ interval: 250 })],
});

player.addEventListener('volumechange', (e) => {
  console.log(e.detail.volume, e.detail.muted);
});
```

**Strategy (S3):**
1. **Hook setters.** Extension wraps `setVolume`/`mute`/`unMute`. As soon as the wrapper's Promise resolves, the extension reads the cached previous value, computes the new value, and (if changed) emits `volumechange`. No waiting for the next poll tick. The cache is updated in the same step so the next poll sees no diff and does not re-emit.
2. **Poll.** Extension runs `setInterval(check, interval)` while attached. `check` calls `getVolume()` + `isMuted()`, compares to a cached last value, emits on diff. Catches changes initiated by the user from within the YouTube iframe UI (volume slider).
3. **Dedupe.** Both paths update and read the same cached `{ volume, muted }`. Hook fires immediately, poll only fires when its read disagrees with the cache. No double-emit on round-trips.
4. **Lifecycle.** Polling only runs while attached (i.e., while a `volumechange` listener exists). `interval` defaults to `250`.

**TypeScript augmentation.** Built-in extensions ship a `declare module '@bogdanrn/yt-embed'` block that extends `YTEmbedEventMap` with their event types. Importing `volumeChangeExtension` automatically gives `volumechange` autocomplete on `addEventListener`.

### 4.4 User extensions

The `Extension` interface is exported. User-authored extensions are not special — they follow the same shape and same lazy attach/detach lifecycle. User extensions augment `YTEmbedEventMap` themselves if they want autocomplete; runtime works regardless.

## 5. Module-level state

The YT iframe API is a true singleton (one global `window.YT`, one `<script>`). The package keeps a module-private cached `Promise<typeof YT>` exposed via an internal `loadIframeApi()` function. The first `new YTEmbed()` triggers the load; subsequent instances share the result.

Implementation rules:
- No `window` or `document` access at module top-level.
- The `<script>` tag is created and appended **inside** `loadIframeApi`, not at import time.
- Always `https://www.youtube.com/iframe_api`.
- The function chains any pre-existing `window.onYouTubeIframeAPIReady` (other libraries on the page may already have registered one).
- Resolves with the global `YT` object after `onYouTubeIframeAPIReady` fires; rejects on `<script>` `error` with `IframeApiLoadError`.

`YTEmbed.config` (static) exposes `{ scriptUrl?: string }` so consumers can override the URL if Google ever changes it without waiting on a package patch.

## 6. Drift resilience (Google API additions)

| Google does | Package response | Maintenance cost |
|---|---|---|
| Adds new method to `YT.Player` | `@types/youtube` updates → autogen extends `FunctionName` → `player.call('newMethod', …)` works immediately. Hand-typed wrapper is optional sugar. | Zero |
| Adds new event callback (`onLiveBroadcastStart`) | `eventCallbackNames` autogen extends → wrapper auto-registers and re-emits as `livebroadcaststart` `CustomEvent`. `addEventListener('livebroadcaststart', …)` works runtime; `YTEmbedEventMap` lags one PR for autocomplete typing. | Zero runtime; one-line type addition |
| Adds new player state (e.g. `7 = LIVE`) | `state` getter passes the number through; `PlayerStateCode` widens via `@types/youtube` upgrade. | One-line widening |
| Renames a method | Wrapper signature breaks at typecheck on next `@types/youtube` Renovate bump. CI fails before merge. | One PR |
| Removes a method | Same as rename. May warrant a major version. | One PR, possibly major |
| Changes `<script>` URL or `window.YT` shape | Users override via `YTEmbed.config.scriptUrl`; default updated in patch. | Zero for users |

Concrete mechanisms:
1. Wrappers are thin `(...args, opts?) => exec('playVideo', args, opts)`. No state-machine logic embedded per-method.
2. Names (function and event) are autogen — the public surface is structurally tied to `@types/youtube`.
3. CI guard fails on uncommitted autogen drift (see §7).
4. Renovate / Dependabot bumps `@types/youtube`; combined with (3), every Google API addition appears as a small, reviewable PR.
5. No hand-curated state machine. `awaitState` is generic ("wait for any next state change").
6. Tests verify the contract (we forward arguments to `YT.Player.playVideo`), not the underlying behavior (Google's job).

Realistic maintenance: roughly one small Renovate review PR per quarter; a real PR only on rename/removal (rare — IFrame API has been stable for years).

## 7. Code generation

A single `scripts/generate.ts` (run in `prebuild` and CI) emits all generated artifacts.

### 7.1 Mechanism

`ts-morph` with the project's own `tsconfig.json`:

```ts
import { Project } from 'ts-morph';

const project = new Project({ tsConfigFilePath: 'tsconfig.json' });

const yt = project.getSourceFiles()
  .flatMap(f => f.getModules())
  .find(m => m.getName() === 'YT')!;

const methods = yt.getInterfaceOrThrow('Player').getMethods()
  .map(m => m.getName()).sort();

const events = yt.getInterfaceOrThrow('Events').getProperties()
  .map(p => p.getName())
  .filter(n => n.startsWith('on'))
  .sort();
```

Resolution flows through TypeScript's native module-resolution path (driven by tsconfig). No filesystem path string is hardcoded; works identically under pnpm, npm, yarn, and bun.

### 7.2 Outputs

Four generated artifacts, all committed and all carrying an auto-generated header (`// AUTO-GENERATED. Do not edit.` for `.ts`, `<!-- AUTO-GENERATED. Do not edit. -->` for `.md`):

- `src/functionNames.generated.ts`
  ```ts
  export const functionNames = ["addEventListener", "cuePlaylist", …] as const;
  export type FunctionName = (typeof functionNames)[number];
  ```
- `src/eventCallbackNames.generated.ts`
  ```ts
  export const eventCallbackNames = ["onApiChange", "onError", …] as const;
  export type EventCallbackName = (typeof eventCallbackNames)[number];
  ```
- `docs/methods.md` and `docs/events.md` — markdown tables documenting the surface (D2). README includes them via marker pairs:
  ```md
  <!-- methods:start -->
  …generated table…
  <!-- methods:end -->
  ```

### 7.3 CI drift guard

`.github/workflows/ci.yml` runs:

```yaml
- run: pnpm run generate
- run: git diff --exit-code src/*.generated.ts docs/methods.md docs/events.md
```

Any uncommitted drift between `@types/youtube` and our committed artifacts fails the build.

## 8. Documentation

Two layers, both autogenerated.

### 8.1 API reference (D1)

`typedoc` + `typedoc-plugin-markdown` reads `src/index.ts` and emits markdown to `docs/api/`. Markdown output is preferred over HTML because:
- It is browseable on GitHub directly without a Pages deployment.
- It composes with the README include markers (D2) into a single Markdown toolchain.
- A future migration to VitePress / Docusaurus / Astro Starlight is trivial — those tools all consume Markdown.

### 8.2 Surface tables in README (D2)

The same `scripts/generate.ts` emits `docs/methods.md` and `docs/events.md`. The README contains include markers; a small post-process step (or markdown-include plugin) inlines them. Result: the README's method and event tables always reflect Google's current API surface, with zero hand-edits.

### 8.3 Hosting

Optional GH Pages publish from the `docs/` folder via `actions/deploy-pages` in the release workflow. Not required for the package to function — `docs/` on the default branch is sufficient for browsing.

## 12. Test outline

`test/YTEmbed.test.ts`
- Constructor accepts both `HTMLElement` and string id; `TypeError` on missing id.
- `addEventListener('statechange', fn, { signal })` fires on YT `onStateChange`; removes on `signal.abort()`.
- `playVideo()`/`pauseVideo()`/`seekTo()` queue before ready, resolve in call order after ready.
- `whenReady()` resolves after `onReady`; multiple calls share one promise.
- `destroy()` is idempotent — second call does not throw.
- `destroy()` rejects pending method promises with `PlayerDestroyedError`.
- Constructor `signal` aborted → triggers `destroy()`.
- `awaitState: true` resolves on next `statechange` event.
- `awaitState: true, signal: AbortSignal.timeout(N)` rejects on timeout (`AbortError`).
- `call('playVideo')` works for hand-typed methods AND for arbitrary names.
- React StrictMode simulation: instantiate twice on same target, destroy both, no leaked iframes or listeners.

`test/loadIframeApi.test.ts`
- Injects exactly one `<script>` across N concurrent calls.
- Resolves with `window.YT` after `onYouTubeIframeAPIReady`.
- Rejects with `IframeApiLoadError` on `<script>` `error` event.
- Chains a pre-existing `window.onYouTubeIframeAPIReady`.
- Always uses `https:`.
- Importing the package in plain Node (no jsdom) does not throw — SSR-safe.
- `YTEmbed.config.scriptUrl` override is honored.

`test/extensions/volumeChange.test.ts`
- Polling timer is **not** running until first `volumechange` listener is added.
- Polling timer **is** running while a listener is attached.
- Polling timer stops when the last listener is removed.
- Hook fires immediately after our `setVolume`/`mute`/`unMute` resolves.
- Polling catches a synthetic in-iframe volume change.
- No double-emit on round-trips (cache-dedupe).
- `destroy()` cleans up the timer.

`test/types.test-d.ts` (`vitest typecheck`)
- `addEventListener('statechange', e => e.detail.state)` types `state` as `PlayerStateCode`.
- `player.call('seekTo', 5, true)` accepts the right arg tuple.
- `player.playVideo({ awaitState: true })` typechecks.
- After `import { volumeChangeExtension }`, `addEventListener('volumechange', …)` autocompletes and types `e.detail` as `{ volume: number; muted: boolean }`.

`test/codegen.test.ts`
- Runs `generate` in-process, asserts no diff against committed artifacts (drift guard).

Coverage target: ≥80% on `src/`.

### 14.3 Branch protection (rulesets, not classic)

Rulesets are GitHub's current branch-protection mechanism and supersede classic branch protection. Solo-dev-friendly: block direct push, require status checks, **do not require review approval**.

```bash
gh api -X POST "repos/$OWNER/$REPO/rulesets" --input - <<'JSON'
{
  "name": "main protection",
  "target": "branch",
  "enforcement": "active",
  "conditions": {
    "ref_name": { "include": ["~DEFAULT_BRANCH"], "exclude": [] }
  },
  "rules": [
    { "type": "deletion" },
    { "type": "non_fast_forward" },
    {
      "type": "pull_request",
      "parameters": {
        "required_approving_review_count": 0,
        "dismiss_stale_reviews_on_push": true,
        "require_code_owner_review": false,
        "require_last_push_approval": false,
        "required_review_thread_resolution": true
      }
    },
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": true,
        "required_status_checks": [
          { "context": "ci" }
        ]
      }
    }
  ],
  "bypass_actors": [
    { "actor_id": 5, "actor_type": "RepositoryRole", "bypass_mode": "always" }
  ]
}
JSON
```

Notes:
- `actor_id: 5` is the built-in **Admin** role. Solo dev keeps an emergency escape hatch.
- `required_approving_review_count: 0` means a PR is the gate, but you can self-merge without an approving review.
- `required_status_checks.context: "ci"` matches the single job name in `ci.yml`. The job runs typecheck, lint, test, build, and the autogen drift check as steps. If `ci.yml` is later split into multiple jobs, list each name here.
- Rulesets allow direct API JSON; safer than chaining `gh api -F` flags for nested arrays.

### 14.6 CodeRabbit installation

`.coderabbit.yaml` is committed; the GitHub App still needs explicit installation per repo. Not automatable via `gh` (CodeRabbit owns the installation flow). One-time manual step:

1. Visit `https://github.com/apps/coderabbitai`.
2. Install on `bogdanrn/youtube-player`.
3. CodeRabbit reads `.coderabbit.yaml` automatically on the next PR.

This is the only manual step in the bootstrap.

### 14.7 Bootstrap script

All automated steps live in `scripts/bootstrap-repo.sh`. Running it on a freshly-created clone (after the local files are written) sets up the GitHub side end-to-end. The script is idempotent enough to re-run safely; failures on already-existing resources are handled with `|| true` where the API returns conflict codes.

## 15. Out of scope (v1)

- Framework adapter packages (`@bogdanrn/yt-embed-react`, `…-svelte`). README provides recipes; spin out only if there is pull.

- A "compat shim" for any older API. The package has no users to keep happy.

- Real-browser CI (Playwright/Cypress). `jsdom` + mocked `window.YT` is sufficient for v1.
